# 风险定级指南（Risk Classification Guide）

本文档为 TOSKill 提供等保视角的漏洞风险分级标准、评分矩阵、置信度评估与漏洞基线评分，用于在扫描结果研判、报告生成与整改优先级排序时统一尺度。

---

## 一、风险分级总览

TOSKill 采用五级风险分类体系，与 CVSS 3.1 评分及等保 2.0 风险评价对齐。

| 风险等级 | 标签 | CVSS 区间 | 等保风险评价 | 响应时限 | 整改要求 |
|----------|------|-----------|--------------|----------|----------|
| 严重 | critical | 9.0-10.0 | 高风险 | 24 小时内 | 立即修复或下线 |
| 高危 | high | 7.0-8.9 | 高风险 | 72 小时内 | 限时修复 + 临时缓解 |
| 中危 | medium | 4.0-6.9 | 中风险 | 下一版本修复 | 排期修复 |
| 低危 | low | 0.1-3.9 | 低风险 | 季度内修复 | 加固建议 |
| 信息 | info | 0 / N/A | - | 视情况 | 最佳实践建议 |

> 等保测评中，"高风险"漏洞未整改将直接影响测评结论；关键控制点（身份鉴别、访问控制、安全审计）的高危漏洞可直接判定测评不通过。

---

## 二、各等级判定依据与示例

### 2.1 严重（critical）

**判定依据**（满足任一即可）：
- 可未授权远程执行任意代码（RCE）
- 可未授权获取系统/数据库管理员权限
- 可未授权读取或篡改核心业务数据（用户数据、财务数据、密钥）
- 可直接控制关键基础设施设备（防火墙、VPN 网关、域控）
- 可绕过身份认证并以特权身份操作系统

**典型示例**：
- Apache Log4j JNDI 注入（CVE-2021-44228，CVSS 10.0）
- Apache Struts 2 OGNL 注入（CVE-2017-5638，CVSS 10.0）
- SQL 注入可回显且可写入文件（`INTO OUTFILE`）
- 未授权文件上传可直接执行 WebShell
- 防火墙/VPN 网关未授权 RCE（如 CVE-2024-3400、CVE-2024-21762）

**等保对应**: 违反 8.1.4.1 身份鉴别、8.1.4.4 应用安全，直接构成高风险。

### 2.2 高危（high）

**判定依据**（满足任一即可）：
- 需低权限认证后可远程执行代码
- 可获取敏感数据但需多步利用或特定条件
- 存储型 XSS 影响大量用户且可窃取凭据
- SSRF 可访问内网核心服务（Redis、数据库、元数据）
- 弱口令可获取管理员权限
- 可越权执行关键业务操作（转账、改密、数据导出）
- 时间盲注可逐字节提取数据

**典型示例**：
- Spring4Shell（CVE-2022-22965，CVSS 9.8，条件需 JDK 9+）
- CitrixBleed 会话令牌泄露（CVE-2023-4966，CVSS 9.4）
- 存储型 XSS 可窃取管理员 Cookie
- SSRF 结合 Redis 未授权写入 SSH Key
- 已知默认口令获取后台管理权限

**等保对应**: 违反 8.1.4.2 访问控制、8.1.4.4 应用安全，构成高风险或中风险偏高。

### 2.3 中危（medium）

**判定依据**（满足任一即可）：
- 需用户交互的客户端漏洞（反射型 XSS、CSRF）
- 信息泄露但不含核心凭据（版本号、内部路径、调试信息）
- SSRF 仅可探测内网端口不可访问服务
- 越权仅可查看非敏感数据
- 目录遍历但权限受限
- 会话管理缺陷（会话不失效、固定会话）

**典型示例**：
- 反射型 XSS 需用户点击且无法窃取 Cookie
- CSRF 可修改用户昵称等非关键配置
- 错误页面泄露框架版本与物理路径
- SSRF 仅可探测内网端口开放情况

**等保对应**: 违反 8.1.4.4 应用安全，构成中风险。

### 2.4 低危（low）

**判定依据**（满足任一即可）：
- 安全配置缺失但不直接导致入侵
- 缺少安全响应头（HSTS、X-Frame-Options 等）
- 使用不安全的 HTTP 方法（PUT/DELETE）
- 目录列表开启
- HTTP 明文传输（无 TLS）
- Cookie 缺少 HttpOnly/Secure 属性

**典型示例**：
- 未启用 HSTS
- `X-Powered-By` 头泄露技术栈
- HTTP 方法 TRACE 开启
- Cookie 未设置 SameSite

**等保对应**: 部分对应 8.1.2.2 通信传输、8.1.4.4 应用安全，构成低风险。

### 2.5 信息（info）

**判定依据**：
- 不构成直接威胁的最佳实践建议
- 安全加固与配置优化建议
- 合规性提示（如密码策略建议）

**典型示例**：
- 建议启用双因素认证
- 建议定期备份验证
- 建议部署 WAF
- 建议实施安全开发生命周期（SDL）

## 三、风险评分矩阵（可能性 × 影响）

风险评分 = 可能性评分 × 影响评分，最终映射至五级分类。

### 3.1 可能性评分（Likelihood，1-5）

| 评分 | 可能性等级 | 判定条件 |
|------|------------|----------|
| 5 | 极高 | 无需认证、可远程利用、公开 PoC、自动化批量 |
| 4 | 高 | 需低权限认证或特定条件，有公开 PoC |
| 3 | 中 | 需中等权限或用户交互，PoC 不公开 |
| 2 | 低 | 需高权限或物理访问，利用复杂 |
| 1 | 极低 | 理论可利用，无已知利用方式 |

### 3.2 影响评分（Impact，1-5）

| 评分 | 影响等级 | 判定条件 |
|------|----------|----------|
| 5 | 灾难性 | 系统完全控制、核心数据泄露/篡改、服务完全中断 |
| 4 | 严重 | 特权权限获取、敏感数据泄露、部分服务中断 |
| 3 | 中等 | 普通权限提升、非敏感数据泄露、有限业务影响 |
| 2 | 轻微 | 信息泄露（版本、路径）、有限越权 |
| 1 | 可忽略 | 配置建议、加固提示 |

### 3.3 风险评分矩阵

| 可能性 \ 影响 | 1（可忽略） | 2（轻微） | 3（中等） | 4（严重） | 5（灾难性） |
|---------------|-------------|-----------|-----------|-----------|-------------|
| 5（极高） | 5（低） | 10（中） | 15（高） | 20（严重） | 25（严重） |
| 4（高） | 4（低） | 8（中） | 12（中） | 16（高） | 20（严重） |
| 3（中） | 3（低） | 6（中） | 9（中） | 12（中） | 15（高） |
| 2（低） | 2（信息） | 4（低） | 6（中） | 8（中） | 10（中） |
| 1（极低） | 1（信息） | 2（信息） | 3（低） | 4（低） | 5（低） |

### 3.4 评分区间映射

| 评分区间 | 风险等级 |
|----------|----------|
| 17-25 | 严重（critical） |
| 12-16 | 高危（high） |
| 7-11 | 中危（medium） |
| 3-6 | 低危（low） |
| 1-2 | 信息（info） |

## 四、置信度评估参考标准

TOSKill 在漏洞研判时输出置信度（confidence），用于标识扫描结果的可信程度，辅助人工复核决策。

### 4.1 置信度等级

| 置信度 | 标签 | 分值区间 | 含义 | 处理建议 |
|--------|------|----------|------|----------|
| 确定 | confirmed | 95-100 | 已手工验证或 PoC 成功复现 | 直接定级，无需复核 |
| 高 | high | 75-94 | 多维度证据交叉验证，误报概率低 | 可直接采纳，抽检即可 |
| 中 | medium | 50-74 | 单一证据，需进一步验证 | 建议人工复核 |
| 低 | low | 25-49 | 间接特征或启发式判断 | 必须人工复核 |
| 极低 | very_low | 0-24 | 仅基于版本号推测或规则模糊匹配 | 标记待验证，不直接入报告 |

### 4.2 置信度判定要素

| 要素 | 加分项（+） | 减分项（-） |
|------|-------------|-------------|
| 证据类型 | 实际回显/PoC 执行成功（+30）、响应内容匹配（+20） | 仅版本号匹配（-20）、仅启发式特征（-15） |
| 验证次数 | 多次请求结果一致（+15）、不同参数均触发（+10） | 单次请求、结果不稳定（-10） |
| 环境因素 | 测试环境与生产一致（+10）、有源码确认（+20） | 环境差异大（-10）、WAF 干扰（-10） |
| 工具一致性 | 多工具结果一致（+15） | 仅单一工具检出（-10） |
| 误报历史 | 该规则历史误报率低（+10） | 该规则历史误报率高（-20） |

### 4.3 置信度与报告呈现

- **confirmed/high**: 直接写入报告，附 PoC 证据
- **medium**: 写入报告但标注"待复核"，附验证建议
- **low/very_low**: 不直接写入正式报告，纳入"待验证清单"供人工复核

## 六、上下文调整规则

基线评分可依据以下上下文因素调整，最终等级 = 基线等级 ± 调整因子。

| 上下文因素 | 调整方向 | 调整幅度 | 说明 |
|------------|----------|----------|------|
| 资产为三级及以上系统 | 升级 | +1 档 | 等保强制要求，风险容忍度低 |
| 资产为核心业务系统 | 升级 | +1 档 | 业务中断影响大 |
| 漏洞位于互联网暴露面 | 升级 | +1 档 | 攻击面广，可能性高 |
| 漏洞位于内网 | 降级 | -1 档 | 需先突破边界 |
| 存在已知 PoC/EXP | 升级 | +1 档 | 利用门槛低 |
| 已在 KEV 目录 | 升级 | +1 档 | 确认在野利用 |
| 需要 MFA 绕过 | 维持 | 0 | MFA 不是漏洞，不调整 |
| WAF 已拦截 | 降级 | -1 档 | 纵深防御降低可能性 |
| 漏洞组件已下线 | 降级 | 降至 info | 不再暴露 |
| 数据已脱敏 | 降级 | -1 档 | 降低影响 |

> 调整后等级不超过 critical，不低于 info。同一漏洞多个调整因子叠加时取最高调整幅度，不累加。

## 七、与 TOSKill 的集成要点

- **自动定级**: 扫描结果依据基线评分 + 上下文调整自动输出风险等级
- **置信度标注**: 每条漏洞附置信度分值，低置信度结果进入待验证队列
- **报告呈现**: 报告中按风险等级排序，每条漏洞标注 CVSS、等保条款、置信度
- **整改优先级**: 基于"风险等级 × 修复成本"输出整改顺序建议
- **等保映射**: 风险等级与等保风险评价（高/中/低）自动关联，支撑测评结论
- **趋势追踪**: 支持按时间维度统计风险等级分布变化，评估安全态势演进
