# 错误处理与异常恢复策略库

本文档定义了AI在遇到错误和异常情况时的处理策略，确保扫描流程的健壮性。

---

## 一、网络错误处理

### 错误类型1: 连接超时

**识别特征**:
- 错误信息包含 "timeout", "timed out"
- 响应时间超过阈值
- 连接建立失败

**处理策略**:
```
1. 重试机制: 最多重试3次，间隔递增(5s, 10s, 20s)
2. 降级策略: 增加超时时间，降低并发数
3. 用户通知: 连续失败时通知用户
4. 记录日志: 记录失败详情供分析
```

**决策示例**:
```
Thought: 目标连接超时，可能是网络问题或目标响应慢
Action: 重试并增加超时时间
Reason: 网络波动常见，重试可解决临时问题
Confidence: 0.7
```

### 错误类型2: DNS解析失败

**识别特征**:
- 错误信息包含 "DNS", "resolve", "name or service not known"
- 域名无法解析

**处理策略**:
```
1. 检查域名格式是否正确
2. 尝试使用IP地址
3. 通知用户检查域名有效性
4. 跳过当前检测，继续其他任务
```

### 错误类型3: 连接被拒绝

**识别特征**:
- 错误信息包含 "Connection refused", "ECONNREFUSED"
- 端口未开放或服务未运行

**处理策略**:
```
1. 记录端口状态为关闭
2. 跳过该端口的后续检测
3. 更新端口扫描结果
4. 继续其他端口检测
```

## 二、认证错误处理

### 错误类型1: 认证过期

**识别特征**:
- HTTP状态码 401
- 响应包含 "token expired", "session expired"
- 需要重新登录

**处理策略**:
```
1. 检查是否有刷新Token机制
2. 尝试重新获取认证
3. 降级为未认证模式
4. 通知用户重新认证
```

**重试策略**:
```
最大重试次数: 3
重试间隔: 5秒
失败后: 通知用户手动认证
```

### 错误类型2: 权限不足

**识别特征**:
- HTTP状态码 403
- 响应包含 "forbidden", "access denied"
- 功能需要更高权限

**处理策略**:
```
1. 记录权限不足的功能
2. 尝试其他可访问的功能
3. 通知用户权限问题
4. 建议提升权限或更换账户
```

### 错误类型3: 认证信息无效

**识别特征**:
- 认证信息格式错误
- 认证信息被篡改
- 认证服务器不可达

**处理策略**:
```
1. 清除无效认证信息
2. 尝试获取新认证
3. 使用未认证模式继续
4. 记录问题供用户查看
```

## 三、WAF/防护错误处理

### 错误类型1: IP被封禁

**识别特征**:
- 所有请求返回403
- 响应包含 "blocked", "banned"
- 连续请求失败

**处理策略**:
```
1. 停止当前扫描
2. 等待冷却时间(5-10分钟)
3. 通知用户情况
4. 建议更换IP或使用代理
```

### 错误类型2: 请求被拦截

**识别特征**:
- 特定Payload被拦截
- 响应包含WAF拦截页面
- HTTP状态码403/406

**处理策略**:
```
1. 记录被拦截的Payload
2. 尝试绕过技术:
   - URL编码
   - 大小写混合
   - 注释插入
   - 分块传输
3. 降低请求频率
4. 更换Payload模板
```

### 错误类型3: 频率限制

**识别特征**:
- 响应包含 "rate limit", "too many requests"
- HTTP状态码 429
- 请求被限流

**处理策略**:
```
1. 降低请求频率
2. 增加请求间隔
3. 等待限流解除
4. 分批执行检测
```

## 四、工具执行错误处理

### 错误类型1: 工具不存在

**识别特征**:
- 工具名称无效
- 工具未注册

**处理策略**:
```
1. 检查工具名称拼写
2. 使用模糊匹配查找相似工具
3. 跳过该工具，继续其他检测
4. 通知用户工具不可用
```

### 错误类型2: 工具参数错误

**识别特征**:
- 参数格式不正确
- 必需参数缺失
- 参数值超出范围

**处理策略**:
```
1. 验证参数格式
2. 使用默认参数值
3. 请求用户提供参数
4. 记录参数错误详情
```

### 错误类型3: 工具执行超时

**识别特征**:
- 工具执行时间超过限制
- 进程无响应

**处理策略**:
```
1. 终止当前执行
2. 记录超时信息
3. 尝试简化检测范围
4. 继续其他检测
```

## 五、数据错误处理

### 错误类型1: 响应解析失败

**识别特征**:
- JSON/XML解析错误
- 响应格式不符合预期

**处理策略**:
```
1. 记录原始响应
2. 尝试多种解析方式
3. 使用正则表达式提取
4. 标记为解析失败，继续处理
```

### 错误类型2: 数据不完整

**识别特征**:
- 响应被截断
- 关键字段缺失

**处理策略**:
```
1. 重试请求获取完整数据
2. 使用已有数据进行分析
3. 标记数据不完整
4. 在报告中说明
```

### 错误类型3: 数据格式变化

**识别特征**:
- 响应结构与预期不符
- 字段名称变化

**处理策略**:
```
1. 分析新的响应格式
2. 更新解析逻辑
3. 使用模糊匹配
4. 记录格式变化
```

## 六、系统错误处理

### 错误类型1: 内存不足

**识别特征**:
- MemoryError
- 系统响应缓慢

**处理策略**:
```
1. 清理缓存数据
2. 减少并发数
3. 分批处理数据
4. 重启扫描流程
```

### 错误类型2: 磁盘空间不足

**识别特征**:
- IOError: No space left
- 写入失败

**处理策略**:
```
1. 清理临时文件
2. 压缩日志文件
3. 通知用户清理空间
4. 暂停扫描等待空间
```

### 错误类型3: 进程异常终止

**识别特征**:
- 进程意外退出
- 子进程崩溃

**处理策略**:
```
1. 记录崩溃信息
2. 从检查点恢复
3. 重启失败的任务
4. 通知用户异常情况
```

## 七、错误恢复流程

### 恢复流程图

```
错误发生
    ↓
识别错误类型
    ↓
选择恢复策略
    ↓
执行恢复操作
    ↓
┌───────────────┐
│ 恢复成功？     │
├───────┬───────┤
│ 是    │ 否    │
↓       ↓
继续执行  通知用户
```

### 恢复优先级

| 优先级 | 恢复策略 | 适用场景 |
|-------|---------|---------|
| 1 | 自动重试 | 临时性错误 |
| 2 | 降级执行 | 功能受限 |
| 3 | 替代方案 | 工具失败 |
| 4 | 用户介入 | 无法自动恢复 |

## 八、错误日志记录

### 日志格式

```json
{
  "timestamp": "2024-01-15T10:30:00Z",
  "session_id": "abc123",
  "error_type": "ConnectionTimeout",
  "error_message": "Connection timed out after 30 seconds",
  "tool": "sqli_scan",
  "target": "http://example.com",
  "retry_count": 2,
  "recovery_action": "retry_with_increased_timeout",
  "recovery_result": "success"
}
```

### 日志级别

| 级别 | 说明 | 示例 |
|-----|------|------|
| DEBUG | 调试信息 | 重试详情 |
| INFO | 一般信息 | 恢复操作 |
| WARNING | 警告信息 | 降级执行 |
| ERROR | 错误信息 | 恢复失败 |
| CRITICAL | 严重错误 | 系统崩溃 |

## 九、用户通知策略

### 通知时机

| 情况 | 通知级别 | 通知内容 |
|-----|---------|---------|
| 自动恢复成功 | INFO | 简要说明 |
| 自动恢复失败 | WARNING | 详细错误和建议 |
| 需要用户操作 | ERROR | 明确的操作指引 |
| 系统严重错误 | CRITICAL | 紧急处理建议 |

### 通知格式

```
类型: [错误类型]
描述: [错误描述]
影响: [对扫描的影响]
建议: [用户可采取的行动]
状态: [当前处理状态]
```
