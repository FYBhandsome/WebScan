# 漏洞与等保技术要求的证据映射

> 用途：为扫描报告提供可追溯的控制项关联线索
> 重要限制：映射不等于不符合判定，不产生固定扣分或符合度百分比
> 最后复核：2026-08-14

## 一、映射原则

- 一个漏洞可以关联多个控制项主题，不能强制压缩为单一条款。
- 映射必须说明适用条件和所需证据。
- 风险严重度由漏洞影响和可利用条件确定，不由条款编号决定。
- 未执行相关工具、测试入口不足或结果不确定时，应标记为 `not_assessed` 或 `inconclusive`。
- “未发现”只表示已测试范围内没有观察到风险，不表示控制项满足。

## 二、漏洞类型映射

| 漏洞/配置类型 | 主要关联主题 | 可能相关主题 | 最低证据要求 |
|---|---|---|---|
| SQL注入 | 8.1.3.2 访问控制、8.1.3.4 入侵防范 | 8.1.3.3 安全审计 | 参数、Payload类型、请求响应差异、可重复性 |
| XSS | 8.1.3.4 入侵防范 | 8.1.3.2 访问控制、8.1.3.3 安全审计 | 输入点、输出上下文、编码情况、浏览器可执行性 |
| OS命令注入 | 8.1.3.4 入侵防范、8.1.3.2 访问控制 | 8.1.3.1 身份鉴别 | 无害探针、响应或时延证据、执行身份与影响范围 |
| 文件上传缺陷 | 8.1.3.2 访问控制、8.1.3.4 入侵防范 | 恶意代码防范 | 文件校验、存储位置、访问方式、执行权限；禁止写入后门 |
| SSRF | 8.1.2 边界防护、8.1.3.4 入侵防范 | 8.1.1 通信网络 | 授权范围内的回连或响应差异证据；禁止读取云凭据 |
| 弱口令 | 8.1.3.1 身份鉴别 | 8.1.3.2 访问控制 | 受控账户、限速记录、成功鉴别证据和锁定影响 |
| LFI/路径遍历 | 8.1.3.2 访问控制、8.1.3.4 入侵防范 | 8.1.3.3 安全审计 | 非敏感验证文件、路径规范化差异和响应证据 |
| CSRF | 8.1.3.2 访问控制 | 身份鉴别、会话保护 | 敏感操作、会话条件、Token/Origin/SameSite验证结果 |
| HTTP安全头缺失 | 安全通信网络、入侵防范 | 安全区域边界 | 实际响应头、页面用途、HTTPS环境和风险上下文 |
| Cookie属性不安全 | 8.1.3.1 身份鉴别、安全通信网络 | 访问控制 | Cookie用途及Secure、HttpOnly、SameSite属性 |
| CORS错误配置 | 8.1.3.2 访问控制、安全区域边界 | 通信网络 | Origin响应、凭证许可和敏感响应可读性 |
| 信息泄露/公开敏感文件 | 8.1.3.2 访问控制、8.1.3.4 入侵防范 | 安全审计 | URL、访问条件、内容敏感性和响应证据 |
| TLS或证书配置问题 | 安全通信网络 | 身份鉴别 | 协议、证书链、名称、有效期和握手结果 |
| 危险HTTP方法 | 8.1.3.2 访问控制、安全区域边界 | 入侵防范 | 方法声明与无副作用验证结果，不执行修改或删除操作 |

## 三、工具证据覆盖

| 工具 | 主要证据类型 | 默认解释 |
|---|---|---|
| `sqli_scan` | SQL注入 | 风险证据或阴性观察 |
| `xss_scan` | XSS | 风险证据或阴性观察 |
| `csrf_scan` | CSRF防护 | 风险证据、支持性线索或不确定 |
| `fileupload_scan` | 上传校验 | 风险证据或不确定 |
| `cmdi_scan` | 命令注入 | 风险证据或阴性观察 |
| `ssrf_scan` | SSRF | 风险证据或阴性观察 |
| `lfi_scan` | 文件包含/路径遍历 | 风险证据或阴性观察 |
| `weakpass_scan` | 身份鉴别 | 风险证据或不确定 |
| `http_security_headers_scan` | 浏览器侧安全配置 | 支持性线索 |
| `cookie_security_scan` | 会话Cookie配置 | 风险证据或支持性线索 |
| `cors_misconfiguration_scan` | 跨域访问控制 | 高置信度风险证据或阴性观察 |
| `tls_certificate_scan` | TLS和证书配置 | 支持性线索 |
| `http_methods_scan` | HTTP方法配置 | 支持性线索 |
| `dir_brute`、`public_metadata_scan`、`infoleak_scan` | 公开暴露面 | 风险证据或支持性线索 |

其他信息收集工具主要帮助确认资产、入口和适用范围，不直接给出控制项符合性判断。

## 四、禁止的推导

- 禁止按漏洞严重度固定扣减等保符合度。
- 禁止按工具数量直接计算置信度或覆盖率。
- 禁止将“全工具链无漏洞”解释为控制项全部满足。
- 禁止将RAG相似度当作条款映射正确性的证明。
- 禁止根据单次黑盒扫描输出正式等保等级、测评结论或认证意见。

```json
  "review_required": true
}
```
