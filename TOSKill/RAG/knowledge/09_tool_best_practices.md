# 工具使用最佳实践

## 信息收集工具最佳实践

### baseinfo_scan (基础信息收集)
**最佳使用时机**: 扫描第一步
**关键参数**: 无需特殊参数
**输出解读**:
- Server头 → 确定Web服务器类型
- X-Powered-By → 确定后端语言/框架
- Set-Cookie → 分析会话管理机制

**与其他工具配合**:
- 发现Apache → 关注 `.htaccess` 相关漏洞
- 发现IIS → 关注短文件名漏洞
- 发现Nginx → 关注配置错误

### port_scan (端口扫描)
**最佳使用时机**: 信息收集阶段
**关键参数**: 
- 常用端口: 21,22,23,25,80,110,443,445,1433,3306,3389,5432,6379,8080,8443,27017
- 全端口扫描耗时较长，按需选择

**输出解读**:
- 3306开放 → 可能存在MySQL弱口令
- 6379开放 → 可能存在Redis未授权
- 27017开放 → 可能存在MongoDB未授权

### waf_detect_scan (WAF检测)
**最佳使用时机**: 漏洞扫描前
**输出解读**:
- 检测到WAF → 降低请求频率并记录可能的拦截影响
- 未检测到WAF → 可使用标准Payload

**结果边界**:
- WAF识别结果只用于解释响应和控制扫描强度
- 不得根据WAF结果自动扩大目标范围或绕过防护
- 未识别出WAF不代表目标没有其他防护机制

## 漏洞扫描工具最佳实践

### xss_scan (XSS检测)
**检测策略**:
1. 反射型优先 → URL参数注入
2. 存储型 → 表单提交测试
3. DOM型 → 分析前端JS代码

**Payload选择**:
- 基础测试: `<script>alert(1)</script>`
- 绕过测试: `<svg/onload=alert(1)>`
- 编码测试: URL编码、HTML实体编码

**成功率提升**:
- 分析输入点上下文
- 测试所有参数
- 关注HTTP响应头

### sqli_scan (SQL注入检测)
**检测策略**:
1. 单引号测试 → 观察错误
2. 布尔测试 → `1=1` vs `1=2`
3. 时间测试 → `SLEEP(5)`

**数据库识别**:
- MySQL → `version()`, `@@version`
- PostgreSQL → `version()`
- Oracle → `SELECT * FROM v$version`
- SQL Server → `@@version`

**成功率提升**:
- 测试所有参数
- 关注错误回显
- 分析响应差异

### fileupload_scan (文件上传检测)
**检测策略**:
1. 前端绕过 → 禁用JS
2. Content-Type绕过 → 修改MIME类型
3. 扩展名绕过 → 双扩展名、空字节

**WebShell选择**:
- PHP: `<?php eval($_POST['cmd']);?>`
- JSP: `<%Runtime.getRuntime().exec(request.getParameter("cmd"));%>`
- ASPX: `<%@ Page Language="Jscript"%><%eval(Request.Item["cmd"]);%>`

## 扫描模式选择指南

| 场景 | 推荐模式 | 原因 |
|------|----------|------|
| 应急响应 | fast | 快速发现高危漏洞 |
| 定期巡检 | deep | 全面覆盖 |
| 渗透测试 | full | 完整攻击面分析 |
| 单点验证 | 单工具 | 针对性测试 |

## 常见问题排查

### 问题1: 扫描超时
**原因**: 目标响应慢、网络问题
**解决**: 增加超时时间、降低并发

### 问题2: 误报率高
**原因**: Payload不精确、目标特殊响应
**解决**: 分析响应特征、调整阈值

### 问题3: 漏报率高
**原因**: WAF拦截、Payload覆盖不全
**解决**: WAF绕过、扩展Payload字典

### 问题4: 目标无响应
**原因**: IP被封禁、目标宕机
**解决**: 更换IP、确认目标状态
