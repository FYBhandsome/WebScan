# 渗透测试方案模板（Penetration Testing Plan）

本文档为 TOSKill 渗透测试方案生成模块提供规范化模板与要点指引，覆盖计划书、规格书、阶段要点与等保视角要求，便于在 RAG 检索时引用标准化条目。

---

## 一、渗透测试计划书框架

### 1.1 测试目标

- **总体目标**: 验证目标系统在当前网络架构、应用代码、配置策略下的安全性，发现可被利用的安全弱点，评估实际风险等级。
- **具体目标**:
  - 发现对外暴露面（资产、端口、服务、接口）并验证其暴露合理性
  - 检测 OWASP Top 10、CWE Top 25 范围内的典型 Web 漏洞
  - 验证身份认证、访问控制、会话管理、数据保护机制有效性
  - 评估内网横向移动路径与权限提升可能性
  - 出具可量化、可复现的风险清单与整改建议

### 1.2 测试范围

| 范围类别 | 说明 | 示例 |
|----------|------|------|
| 资产范围 | IP、域名、应用、API 清单 | `*.example.com`、`10.0.0.0/24` |
| 测试深度 | 黑盒/灰盒/白盒 | 灰盒（提供测试账号） |
| 排除项 | 不允许触碰的资产或接口 | 生产数据库直连、第三方支付回调 |
| 数据范围 | 允许接触的数据级别 | 仅测试账号数据，禁止触碰真实用户数据 |
| 时间范围 | 允许测试的时间窗口 | 工作日 22:00-06:00 |

### 1.3 方法论

- **依据标准**: GB/T 28448-2019《信息安全技术 网络安全等级保护测评要求》、PTES（Penetration Testing Execution Standard）、OWASP Testing Guide v4.2、NIST SP 800-115。
- **测试类型**:
  - 黑盒测试：模拟外部攻击者，零信息起步
  - 灰盒测试：提供有限账号与架构信息，模拟内网/授权用户
  - 白盒测试：基于源代码、配置、架构图开展代码审计与组合测试
- **攻击链路**: 信息收集 → 威胁建模 → 漏洞分析 → 漏洞利用 → 后渗透 → 报告

### 1.4 时间安排

| 阶段 | 工作日 | 工时占比 | 主要产出 |
|------|--------|----------|----------|
| 启动与信息收集 | D1-D2 | 15% | 资产清单、攻击面地图 |
| 漏洞发现与验证 | D3-D5 | 35% | 漏洞清单（含 PoC） |
| 漏洞利用与后渗透 | D6-D7 | 20% | 利用链、影响证明 |
| 报告编写与复核 | D8-D10 | 30% | 测试报告、整改建议 |

### 1.5 人员分工

| 角色 | 职责 | 资质要求 |
|------|------|----------|
| 项目经理 | 进度把控、客户对接、风险协调 | CISP/CISP-PTE，5年+经验 |
| 主测工程师 | 攻击路径设计、高危漏洞挖掘 | OSCP/OSCE，3年+经验 |
| 测试工程师 | 工具执行、漏洞复现、PoC编写 | CISP-PTE，2年+经验 |
| 报告审核 | 报告质量把关、等保条款映射 | 等保测评师（高级） |
| 应急联系人 | 异常事件响应、回滚协调 | 7×24可达 |

## 二、渗透测试规格书框架

### 2.1 测试环境要求

- **网络隔离**: 测试在独立 VLAN 或跳板机进行，禁止使用生产网直接攻击
- **环境准备**:
  - 提供与生产一致的测试环境（含数据、配置、中间件版本）
  - 提供测试账号集（普通用户、特权用户、只读用户各1个）
  - 提供网络拓扑、IP 分配表、域名清单
- **备份要求**: 测试前完成数据库快照、配置备份，便于异常回滚
- **监控要求**: 开启全流量审计与操作录屏，留存不少于 6 个月

### 2.2 工具清单

| 阶段 | 工具 | 用途 | 授权状态 |
|------|------|------|----------|
| 信息收集 | Nmap、Masscan、Sublist3r、FOFA、Hunter | 端口扫描、子域名、资产测绘 | 商业授权/开源 |
| 漏洞扫描 | TOSKill、AWVS、Nessus、Xray | Web/主机漏洞扫描 | 已授权 |
| 漏洞利用 | SQLMap、Metasploit、Burp Suite Pro | 注入、利用链、流量重放 | 商业授权 |
| 后渗透 | Cobalt Strike、Mimikatz、BloodHound | 内网横向、凭据提取、路径分析 | 仅限授权环境 |
| 报告 | TOSKill 报告模块、Dradis | 漏洞归档、报告生成 | 内部工具 |

> 所有工具须在授权书附件中明确列明，版本号、配置项、运行参数一并备案。

### 2.3 交付物标准

| 交付物 | 格式 | 内容要求 | 交付时间 |
|--------|------|----------|----------|
| 测试方案 | PDF + Word | 范围、方法、时间、人员、风险预案 | 启动前 3 工作日 |
| 漏洞清单 | Excel | 编号、名称、等级、位置、PoC、状态 | 测试中实时更新 |
| 测试报告 | PDF | 执行摘要、漏洞详情、风险分析、整改建议 | 测试结束后 5 工作日 |
| 整改复测报告 | PDF | 修复验证结果、残留风险 | 复测结束后 3 工作日 |
| 原始证据 | 加密压缩包 | 流量包、截图、录屏、PoC 脚本 | 随报告交付 |

## 三、各阶段测试要点

### 3.1 信息收集阶段

- **被动收集**: WHOIS、DNS 历史、证书透明度日志（crt.sh）、GitHub 泄露、网盘泄露、搜索引擎缓存
- **主动收集**: 端口扫描（TCP/UDP）、服务指纹识别、Web 指纹（Wappalyzer/WhatWeb）、子域名爆破、目录爆破（dirsearch/gobuster）
- **关键产出**:
  - 完整资产清单（IP/端口/服务/版本）
  - 技术栈识别结果（语言、框架、中间件、CMS）
  - 历史漏洞关联（基于版本号匹配 CVE）
- **等保关联**: 对应"安全通信网络-网络架构"与"安全管理中心-资产管理"条款，验证资产可见性与暴露面管控

### 3.2 漏洞发现阶段

- **自动化扫描**: TOSKill 全量扫描 + Nessus 主机扫描，覆盖 OWASP Top 10
- **手工测试**:
  - 认证与会话：弱口令、会话固定、会话不失效、JWT 弱密钥
  - 访问控制：越权（水平/垂直）、IDOR、未授权接口
  - 注入类：SQL、NoSQL、命令、LDAP、XPath、模板注入（SSTI）
  - 客户端：XSS（反射/存储/DOM）、CSRF、点击劫持、开放重定向
  - 文件操作：上传、下载、包含、目录遍历
  - 服务端：SSRF、XXE、反序列化、请求走私
- **关键产出**: 漏洞清单（含 CVE/CWE 编号、PoC、影响等级）
- **等保关联**: 对应"安全计算环境-应用安全""安全区域边界-访问控制"

### 3.3 漏洞利用阶段

- **利用链构建**: 将单点漏洞组合为完整攻击链（如 SSRF + Redis 未授权 → RCE）
- **影响证明**:
  - 数据泄露：仅证明可读，禁止下载真实数据（脱敏截图）
  - 权限获取：获取 Shell 后立即记录 whoami/id，禁止驻留
  - 横向移动：仅验证路径可达，不实际植入持久化
- **红线约束**:
  - 禁止删除/篡改数据
  - 禁止 DoS 测试（除非单独授权）
  - 禁止对非授权资产发起攻击
  - 禁止传播获取的凭据与数据
- **等保关联**: 验证"安全计算环境-入侵防范""安全审计-安全审计"实际防护效能

### 3.4 后渗透阶段

- **权限提升**: 内核提权、SUID 滥用、Sudo 配置错误、数据库 UDF
- **凭据收集**: 内存抓取（Mimikatz）、配置文件、浏览器密码、SSH Key
- **横向移动**: Pass-the-Hash、Kerberoasting、WMI/PsExec、RDP 劫持
- **持久化验证**: 仅记录可行路径，不实际植入后门（计划任务、服务、注册表）
- **数据定位**: 标识关键资产位置，验证最小权限原则落实情况
- **痕迹清理**: 测试结束后完整清理测试账号、上传文件、新增计划任务
- **等保关联**: 对应"安全计算环境-恶意代码防范""安全管理中心-集中管控"

### 3.5 报告阶段

- **执行摘要**: 面向管理层，量化风险（漏洞数、等级分布、风险趋势）
- **漏洞详情**: 每条漏洞含位置、原理、PoC、影响、CVSS 评分、整改建议
- **等保映射**: 每条漏洞映射到等保 2.0 具体条款（如 8.1.4.4 应用安全）
- **整改优先级**: 按"风险等级 × 修复成本"矩阵排序
- **复测计划**: 明确复测时间、复测范围、通过标准

## 四、等保视角的渗透测试要求

### 4.1 等保对渗透测试的强制要求

依据 GB/T 28448-2019，第三级及以上系统在测评中应开展渗透测试：

| 等级 | 渗透测试要求 | 测评力度 |
|------|--------------|----------|
| 二级 | 建议开展，可选 | 简单 |
| 三级 | 必须开展，覆盖核心系统 | 一般 |
| 四级 | 必须开展，覆盖全部系统 | 深入 |
| 五级 | 必须开展，特殊行业附加要求 | 深入+特殊 |

### 4.2 渗透测试与等保条款映射

| 渗透测试发现 | 等保条款 | 条款编号 |
|--------------|----------|----------|
| 网络架构暴露面过大 | 安全通信网络-网络架构 | 8.1.2.1 |
| 边界访问控制缺失 | 安全区域边界-访问控制 | 8.1.3.1 |
| 入侵防范失效 | 安全区域边界-入侵防范 | 8.1.3.2 |
| 应用注入漏洞 | 安全计算环境-应用安全 | 8.1.4.4 |
| 身份认证薄弱 | 安全计算环境-身份鉴别 | 8.1.4.1 |
| 越权访问 | 安全计算环境-访问控制 | 8.1.4.2 |
| 日志缺失 | 安全审计-安全审计 | 8.1.4.5 |
| 数据明文传输 | 安全计算环境-数据完整性/保密性 | 8.1.4.6/8.1.4.7 |

### 4.3 渗透测试报告的等保合规要素

- **定级匹配**: 报告需说明系统定级（如三级），并据此判定风险可接受度
- **条款符合性**: 每条漏洞须标注违反的等保条款及对应控制点
- **整改闭环**: 整改建议须可溯源至等保技术/管理要求，便于测评复测
- **证据留存**: 渗透测试过程证据须纳入等保测评档案，留存不少于 6 个月

### 4.4 特殊行业附加要求

- **金融行业**: 参考 JR/T 0071《金融行业网络安全等级保护实施指引》，渗透测试须覆盖移动端与开放银行接口
- **电力行业**: 参考 DL/T 2045，须包含工控协议（IEC 104、Modbus）安全测试
- **医疗卫生**: 参考《医疗卫生机构网络安全管理办法》，须覆盖 HIS、PACS、互联网医院
- **教育行业**: 参考等保 2.0 教育行业扩展要求，覆盖在线教育与一卡通系统

## 五、方案生成注意事项

- **范围确认**: 生成方案前必须与客户确认资产清单与授权边界，避免越权
- **风险预案**: 方案须包含异常事件应急流程（服务中断、数据损坏、误删）
- **法律合规**: 方案须引用《网络安全法》《数据安全法》《个人信息保护法》相关条款
- **保密要求**: 测试过程获取的数据须加密存储、专人保管、测试后销毁
- **工具合规**: 商业工具须提供授权证明，开源工具须记录版本与配置
- **报告脱敏**: 涉及真实用户数据、凭据、密钥的内容须脱敏后再交付

## 六、与 TOSKill 的集成要点

- **方案模板调用**: TOSKill 可基于目标资产自动填充范围、工具、时间表
- **漏洞清单同步**: 测试过程中扫描结果实时回写漏洞清单，自动映射等保条款
- **报告自动生成**: 测试结束后基于漏洞清单与等保映射自动生成报告草稿
- **复测跟踪**: 整改完成后一键触发复测扫描，比对前后差异生成复测报告
