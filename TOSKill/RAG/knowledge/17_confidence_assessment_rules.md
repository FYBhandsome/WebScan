# AI等保评估置信度评判规则

> 用途：为AI评估等保风险等级时提供置信度计算的标准化规则和方法论

---

## 一、评估维度与权重

### 1.1 漏洞检测准确性（权重30%）

**评分标准：**

| 评估子项 | 满分 | 评分依据 |
|---------|------|---------|
| 工具覆盖度 | 40分 | 使用工具数/应使用工具数 |
| 交叉验证率 | 30分 | 多工具检测同一漏洞的比例 |
| 证据充分性 | 30分 | 有payload+响应证据=满分，仅有描述=60% |

**计算公式：**
```
准确性 = (工具覆盖度得分 + 交叉验证得分 + 证据充分性得分) / 100 * 100
```

**工具覆盖度参考：**
- ≥8个工具：40分
- 5-7个工具：30分
- 3-4个工具：20分
- 1-2个工具：10分

### 1.2 等保控制项映射准确度（权重25%）

**评分标准：**

| 评估子项 | 满分 | 评分依据 |
|---------|------|---------|
| RAG检索相似度 | 40分 | 漏洞→等保条款的语义匹配度 |
| 映射覆盖率 | 35分 | 已映射漏洞/总漏洞数 |
| 条款引用准确性 | 25分 | 引用的等保条款编号是否正确 |

**RAG检索相似度参考：**
- 相似度≥0.8：40分
- 相似度0.6-0.8：30分
- 相似度0.4-0.6：20分
- 相似度<0.4：10分

### 1.3 风险等级判定一致性（权重25%）

**评分标准：**

| 评估子项 | 满分 | 评分依据 |
|---------|------|---------|
| 等级偏差度 | 40分 | 与知识库标准等级的偏差 |
| CVSS一致性 | 30分 | CVSS评分与严重度等级的一致性 |
| 跨工具一致性 | 30分 | 多工具检测同一漏洞时结果一致性 |

**等级偏差扣分：**
- 偏差0级（完全一致）：40分
- 偏差1级：30分
- 偏差2级：15分
- 偏差3级以上：0分

### 1.4 整改方案合规性（权重20%）

**评分标准：**

| 评估子项 | 满分 | 评分依据 |
|---------|------|---------|
| 等保条款针对性 | 40分 | 修复建议是否明确引用等保条款 |
| 方案可操作性 | 30分 | 建议是否具体可执行 |
| 合规覆盖度 | 30分 | 整改后预期达到的等保符合度 |

## 二、综合置信度计算

### 2.1 加权计算公式

```
综合置信度 = 准确性 * 0.30 + 映射准确度 * 0.25 + 一致性 * 0.25 + 合规性 * 0.20
```

### 2.2 等级阈值

| 置信度范围 | 等级 | 标签 | 处理建议 |
|-----------|------|------|---------|
| ≥80 | high | 高置信度 | 可直接用于等保合规决策 |
| 60-79 | mid | 中置信度 | 建议安全专家抽检复核 |
| <60 | low | 低置信度 | 必须人工逐项复核 |
| 0 | info | 待评估 | 评估数据不足 |

### 2.3 误差范围计算

| 误差来源 | 范围 | 说明 |
|---------|------|------|
| 工具覆盖度偏差 | ±5% | 取决于工具数量和类型 |
| 知识库匹配偏差 | ±3% | 取决于RAG检索相似度 |
| LLM评估波动 | ±3% | 取决于模型温度和输入稳定性 |
| 综合误差 | ±5% ~ ±8% | 各误差源的叠加 |

**综合误差公式：**
```
综合误差 = sqrt(工具偏差² + 知识库偏差² + LLM偏差²)
        = sqrt(5² + 3² + 3²) ≈ 6.6%
```
取整为 ±5%（保守）或 ±8%（宽松）。

## 三、等保符合度预估

### 3.1 基础符合度

```
基础符合度 = 100% - Σ(各漏洞扣分)
```

### 3.2 符合度修正

```
最终符合度 = 基础符合度 × (置信度等级修正系数)
```

**修正系数：**
- 高置信度：×1.0（不修正）
- 中置信度：×0.95（保守修正）
- 低置信度：×0.90（大幅修正）

### 3.3 示例

发现1个SQL注入（-8%）+ 1个弱口令（-5%）：
- 基础符合度 = 100% - 8% - 5% = 87%
- 若置信度为高（85分）：最终符合度 = 87% × 1.0 = 87% ±5%
- 若置信度为中（70分）：最终符合度 = 87% × 0.95 = 82.65% ±8%

## 四、评估依据充分性判定

### 4.1 评估依据等级

| 依据等级 | 条件 | 置信度加成 |
|---------|------|-----------|
| 充分 | RAG检索到3+条相关条款 + 历史案例匹配 | +5分 |
| 基本 | RAG检索到1-2条相关条款 | 0分 |
| 不足 | RAG未检索到相关条款 | -10分 |

### 4.2 知识库版本要求

- 知识库应包含完整的等保2.0三级标准条款
- 漏洞→等保映射表应覆盖所有扫描工具检测的漏洞类型
- 置信度评判规则应与本文件内容一致

---

## 五、降级规则

### 5.1 RAG不可用时
- 映射准确度维度固定为60分（基于关键词匹配）
- 依据充分性判定为"不足"
- 综合置信度上限为75分（中置信度）

### 5.2 LLM不可用时
- 综合置信度返回0分（待评估）
- 报告显示占位说明
- 不影响其他报告模块的正常生成

### 5.3 漏洞数据不足时
- 漏洞数=0：跳过评估，符合度预估为95%（乐观估计）
- 漏洞数<3：依据充分性判定为"基本"
- 漏洞数≥3：正常评估

## 六、输出数据结构

AI评估应输出以下JSON结构：

```json
{
  "overall_score": 87,
  "level": "high",
  "standard_text": "基于等保2.0（GB/T 22239-2019）三级标准",
  "dimensions": [
    {"label": "漏洞检测准确性", "value": 92},
    {"label": "等保控制项映射准确度", "value": 88},
    {"label": "风险等级判定一致性", "value": 85},
    {"label": "整改方案合规性", "value": 82}
  ],
  "compliance_estimate": 72,
  "compliance_margin": "±5%",
  "kb_refs": "15_mlps_standard, 16_mlps_vuln_mapping",
  "note": "本置信度由AI综合漏洞扫描结果与等保2.0知识库进行多维匹配得出..."
}
```

### 字段说明
| 字段 | 类型 | 说明 |
|------|------|------|
| overall_score | float | 综合置信度（0-100） |
| level | string | 等级：high/mid/low/info |
| standard_text | string | 标准说明文本 |
| dimensions | array | 4个维度的分项得分 |
| compliance_estimate | float | 等保符合度预估（0-100） |
| compliance_margin | string | 误差范围（如±5%） |
| kb_refs | string | 引用的知识库文件 |
| note | string | 评估说明文字 |
