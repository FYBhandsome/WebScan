# AI 决策经验库

本文档是 AI Agent 在不同扫描场景下的决策参考指南，用于指导 AI 在各种情况下选择正确的下一步行动。

---

## 一、初始扫描阶段决策

### 场景1: 用户首次发起扫描请求
**状态**: 无已完成任务，无历史结果
**推荐行动**:
1. 首先执行 `baseinfo_scan` 获取目标基础信息
2. 根据 baseinfo 结果判断技术栈
3. 如果发现 WAF，执行 `waf_detect` 了解防护策略

**决策依据**:
- 信息收集是漏洞扫描的前提
- 了解目标技术栈有助于选择合适的漏洞检测工具
- WAF 检测结果影响后续 Payload 策略

### 场景2: 用户指定"快速扫描"
**状态**: 用户明确要求快速
**推荐行动**:
1. 跳过完整信息收集
2. 直接执行 `xss_scan` 和 `sqli_scan`
3. 仅报告高危漏洞

**决策依据**:
- 快速扫描模式优先发现高危漏洞
- 减少请求量，降低被检测风险

### 场景3: 用户指定"深度扫描"
**状态**: 用户要求全面检测
**推荐行动**:
1. 执行完整信息收集流程
2. 执行全部漏洞检测工具
3. 尝试多种绕过技术

**决策依据**:
- 深度扫描追求覆盖率
- 组合多种检测方法提高发现率

## 二、信息收集后决策

### 场景4: 发现开放端口 3306/5432/27017
**状态**: 端口扫描发现数据库服务
**推荐行动**:
1. 执行 `weakpass_scan` 尝试弱口令
2. 检查数据库默认配置
3. 尝试未授权访问

**决策依据**:
- 数据库服务常存在弱口令
- 默认配置可能导致未授权访问

### 场景5: 发现 WAF/CDN
**状态**: WAF 检测或 CDN 检测返回阳性
**推荐行动**:
1. 记录 WAF 类型/CDN 厂商
2. 调整 Payload 编码策略
3. 降低扫描频率避免封禁
4. 尝试绕过技术（分块传输、编码绕过）

**决策依据**:
- WAF 会拦截常规 Payload
- CDN 可能隐藏真实 IP
- 需要特殊绕过策略

### 场景6: 发现敏感目录/文件
**状态**: 目录扫描发现备份文件、配置文件
**推荐行动**:
1. 下载并分析文件内容
2. 提取敏感信息（数据库密码、API密钥）
3. 根据信息扩大攻击面

**决策依据**:
- 信息泄露是高价值发现
- 可能直接获取系统权限

---

## 三、漏洞检测阶段决策

### 场景7: XSS 检测发现反射点
**状态**: XSS 扫描发现可注入点
**推荐行动**:
1. 尝试多种 XSS 类型（反射型、DOM型）
2. 测试绕过技术（编码、大小写、新标签）
3. 构造实际利用 Payload

**决策依据**:
- 发现注入点后需确认可利用性
- 多种绕过技术提高成功率

### 场景8: SQL 注入发现错误回显
**状态**: SQL 注入测试触发数据库错误
**推荐行动**:
1. 确认注入类型（Union/报错/盲注）
2. 提取数据库信息
3. 尝试获取数据或写入 WebShell

**决策依据**:
- 错误回显意味着高成功率
- 可直接获取敏感数据

### 场景9: 文件上传点发现
**状态**: 发现文件上传功能
**推荐行动**:
1. 测试前端限制绕过
2. 测试 Content-Type 绕过
3. 测试扩展名绕过（双扩展名、空字节）
4. 尝试上传 WebShell

**决策依据**:
- 文件上传可能直接获取服务器权限
- 多种绕过技术组合测试

### 场景10: 发现 SSRF 漏洞
**状态**: SSRF 测试成功
**推荐行动**:
1. 探测内网服务
2. 尝试读取云元数据
3. 利用协议（gopher、dict）攻击内网服务

**决策依据**:
- SSRF 可突破网络边界
- 云环境可能获取高权限凭证

## 四、漏洞发现后决策

### 场景11: 发现高危漏洞
**状态**: 检测到 SQL 注入/RCE/文件上传
**推荐行动**:
1. 立即报告用户
2. 暂停进一步扫描等待用户确认
3. 提供修复建议

**决策依据**:
- 高危漏洞需要立即处理
- 避免造成更大影响

### 场景12: 发现多个中危漏洞
**状态**: 检测到 XSS/CSRF/LFI
**推荐行动**:
1. 继续完成剩余检测
2. 汇总报告所有发现
3. 分析漏洞组合利用可能性

**决策依据**:
- 中危漏洞组合可能提升危害等级
- 完整报告更有价值

### 场景13: 未发现漏洞
**状态**: 所有检测完成，未发现漏洞
**推荐行动**:
1. 报告扫描结果
2. 提供安全加固建议
3. 建议定期复测

**决策依据**:
- 未发现漏洞也是有价值的结果
- 安全加固建议帮助用户提升安全水平

## 五、异常情况决策

### 场景14: 目标无响应/超时
**状态**: 扫描过程中目标不可达
**推荐行动**:
1. 重试 2-3 次
2. 降低并发数
3. 通知用户检查目标状态

**决策依据**:
- 可能是临时网络问题
- 也可能是目标封禁了扫描 IP

### 场景15: WAF 封禁
**状态**: 检测到 IP 被封禁
**推荐行动**:
1. 停止当前扫描
2. 通知用户情况
3. 建议更换 IP 或降低频率

**决策依据**:
- 继续扫描无意义
- 需要用户介入处理

### 场景16: 工具执行失败
**状态**: 单个工具执行报错
**推荐行动**:
1. 记录错误信息
2. 尝试替代工具或方法
3. 继续执行其他检测
4. 在报告中说明失败原因

**决策依据**:
- 单个工具失败不影响整体扫描
- 需要记录问题供后续分析

## 六、用户交互决策

### 场景17: 用户中断扫描
**状态**: 用户请求停止扫描
**推荐行动**:
1. 立即停止当前任务
2. 保存已完成的结果
3. 生成部分报告

**决策依据**:
- 用户有完全控制权
- 已完成的工作应保留

### 场景18: 用户请求修改目标
**状态**: 用户要求更换扫描目标
**推荐行动**:
1. 确认新目标合法性
2. 开始新的扫描会话
3. 保留旧会话记录

**决策依据**:
- 新目标需要新的扫描流程
- 保留历史记录供参考

### 场景19: 用户请求特定检测
**状态**: 用户指定只检测某类漏洞
**推荐行动**:
1. 仅执行用户指定的检测
2. 跳过其他检测
3. 报告聚焦于指定漏洞

**决策依据**:
- 用户明确需求时应精准响应
- 避免不必要的扫描

---

## 七、决策优先级规则

1. **安全优先**: 任何可能造成危害的操作需用户确认
2. **效率优先**: 优先执行高价值检测
3. **完整性优先**: 按计划完成所有检测
4. **用户优先**: 用户指令优先于默认策略

---
