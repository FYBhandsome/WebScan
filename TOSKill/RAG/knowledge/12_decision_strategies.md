# AI决策执行策略库

本文档提供AI在不同扫描阶段的具体执行策略，帮助AI做出更准确的决策。

---

## 一、扫描阶段决策矩阵

### 阶段1: 初始信息收集

**触发条件**: 无已完成任务，用户发起扫描请求

**决策流程**:
```
1. baseinfo_scan → 获取HTTP头、Server信息、技术栈
2. port_scan → 发现开放端口和服务
3. subdomain_scan → 发现子域名（如果目标是域名）
4. dir_brute → 发现公开目录和文件线索
5. waf_detect_scan → 检测WAF/防护设备
```

**决策依据**:
- 信息收集是漏洞发现的基础
- 端口信息决定后续漏洞检测方向
- WAF检测结果影响Payload策略

### 阶段2: 漏洞检测

**触发条件**: 信息收集完成，有端口/服务信息

**端口驱动决策**:
| 开放端口 | 推荐检测工具 | 原因 |
|---------|-------------|------|
| 80/443/8080/8443 | xss_scan, sqli_scan, dir_brute | Web服务，常见漏洞 |
| 3306/5432/27017 | weakpass_scan, sqli_scan | 数据库服务，弱口令风险 |
| 6379 | weakpass_scan | Redis未授权访问 |
| 21 | weakpass_scan | FTP弱口令 |
| 22 | weakpass_scan | SSH弱口令 |
| 3389 | weakpass_scan | RDP弱口令 |

### 阶段3: 深度检测

**触发条件**: 发现潜在漏洞点或可疑功能

**功能驱动决策**:
| 发现功能 | 推荐检测 | Payload策略 |
|---------|---------|------------|
| 搜索框 | sqli_scan, xss_scan | 测试输入点 |
| 文件上传 | fileupload_scan | 多种绕过技术 |
| URL参数 | sqli_scan, xss_scan, ssrf_scan | 参数污染 |
| 表单提交 | xss_scan, csrf_scan | 存储型XSS |

## 二、结果驱动决策

### 情况1: 发现开放端口

**执行策略**:
1. 分析端口对应服务
2. 选择针对性检测工具
3. 优先检测弱口令（数据库、缓存服务）
4. 其次检测服务已知漏洞

**示例**:
```
发现: 3306端口开放
决策: weakpass_scan → sqli_scan
原因: MySQL弱口令是常见入口，SQL注入是高危漏洞
```

### 情况2: 发现WAF

**执行策略**:
1. 记录WAF类型
2. 调整Payload编码策略
3. 降低扫描频率
4. 使用绕过技术

**绕过策略选择**:
| WAF类型 | 推荐绕过技术 |
|--------|-------------|
| 云WAF | 分块传输、编码绕过 |
| ModSecurity | 大小写混合、注释插入 |
| 硬件WAF | 协议利用、编码组合 |
| 自定义过滤 | 标签替换、函数替换 |

### 情况3: 发现敏感文件

**执行策略**:
1. 下载并分析文件内容
2. 提取敏感信息（密码、密钥、配置）
3. 利用信息扩大攻击面
4. 更新后续检测策略

**敏感文件类型**:
- `.git/` → 源码泄露
- `.env` → 环境变量泄露
- `backup.sql` → 数据库备份
- `config.php` → 配置信息
- `robots.txt` → 目录线索

### 情况4: 发现漏洞

**高危漏洞处理**:
1. 立即通知用户
2. 暂停扫描等待确认
3. 提供修复建议
4. 记录详细信息

**中低危漏洞处理**:
1. 继续完成检测
2. 汇总所有发现
3. 分析组合利用可能性

## 三、异常处理决策

### 异常1: 目标无响应

**处理流程**:
```
1. 重试2-3次（间隔5秒）
2. 降低并发数
3. 检查是否被封禁
4. 通知用户检查目标状态
```

**决策输出**:
```
Thought: 目标连续3次无响应，可能被封禁或目标宕机
Action: 通知用户
Reason: 继续扫描无意义，需要用户介入
```

### 异常2: 工具执行失败

**处理流程**:
```
1. 记录错误信息
2. 尝试替代工具
3. 继续其他检测
4. 报告中说明失败原因
```

**替代工具映射**:
| 失败工具 | 替代工具 |
|---------|---------|
| sqli_scan | xss_scan, cmdi_scan |
| xss_scan | csrf_scan |
| fileupload_scan | dir_brute |
| ssrf_scan | csrf_scan |

### 异常3: 认证失效

**处理流程**:
```
1. 检查认证状态
2. 尝试重新获取认证
3. 降级为未认证模式
4. 通知用户
```

## 四、用户交互决策

### 交互1: 用户中断

**处理**:
```
1. 立即停止当前任务
2. 保存已完成结果
3. 生成部分报告
4. 保留会话状态
```

### 交互2: 用户拒绝工具

**处理**:
```
1. 记录拒绝的工具
2. 生成替代方案
3. 等待用户选择
4. 执行用户选择的方案
```

### 交互3: 用户指定目标

**处理**:
```
1. 验证目标格式
2. 创建新扫描会话
3. 开始信息收集
4. 保留历史记录
```

## 五、决策优先级规则

### 优先级排序

1. **安全优先**: 高危操作需用户确认
2. **效率优先**: 先执行高价值检测
3. **完整性优先**: 按计划完成检测
4. **用户优先**: 用户指令优先于默认策略

### 决策权重

| 因素 | 权重 | 说明 |
|-----|-----|------|
| 漏洞严重程度 | 0.4 | 高危漏洞优先处理 |
| 用户指令 | 0.3 | 用户明确要求优先 |
| 检测效率 | 0.2 | 快速发现优先 |
| 完整性 | 0.1 | 覆盖率考虑 |

## 六、决策输出格式

AI决策应输出标准格式：

```
Thought: [分析当前状态、上下文、已发现信息]
Action: [选择的工具名称]
Reason: [选择理由，引用知识库]
Confidence: [置信度 0.0-1.0]
RAG_Reference: [引用的知识库来源]
```

**示例**:
```
Thought: 已完成baseinfo_scan，发现Apache服务器和MySQL数据库(3306端口开放)
Action: weakpass_scan
Reason: 根据知识库"端口驱动决策"，3306端口开放应优先检测弱口令
Confidence: 0.85
RAG_Reference: 12_decision_strategies.md - 端口驱动决策
```
